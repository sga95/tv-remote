# Traffic capture: what the remote talks to

Public version. Addresses, device names and file paths are replaced by roles. The raw capture is kept offline because it contains home network addresses; its fingerprint is given so that it cannot be swapped later.

## What was done

- Where: on the small home server that runs the remote (a Raspberry Pi), on its only active network interface.
- When: 18 November 2026, ten minutes (600 seconds), while the owner used the remote from a phone as usual.
- How: `tcpdump -i <interface> -n -w <file>` with no filter, so everything the machine sent or received was recorded. In parallel, `ss -H -tunap` every 2 seconds (300 samples), to see which program owned each connection.
- Version under test: `remote_fast.py` with SHA-256 `562ee198f79a965a456217bac9c6c01bba2e9fcb53822c25e6eb6ec883afd99e` (release v1.2.0).
- Capture file: 1,991,919 bytes, SHA-256 `2443f41a074509fc24d55a9c704f871f9e5af4ac0125048142403f28c4de10ca`. 14,560 packets captured, 0 dropped by the kernel.
- Connection log: 1,075,576 bytes, SHA-256 `2efe049554f02dfc0fcfdaa11f7184fa0f0354310898287cc3bc983a8171f34d`.

Roles: **tv** is the peer on the adb port, **phone** is the only peer on the remote's port, **router** is the default gateway, **server** is the machine running the remote.

## Per program

Over all 300 samples:

- The remote (python) listened on its port, had connections only with the phone, and made two connection attempts to the TV's adb port (its "is the TV reachable" check).
- adb listened on the loopback interface only, and connected only to loopback and to the TV's adb port.
- No DNS query left the server.

## The one public address

One address outside the home appears: a public time server, 4 packets out and 4 back, 48 bytes each, standard NTP. It keeps the server's clock right. It was attributed to the system time service by elimination (it is the only NTP client on the machine, and the remote and adb never had a UDP socket in any sample); the exchange is shorter than the 2-second sampling, so it was not seen directly.

## What this shows

In those ten minutes, with that version, the remote and adb exchanged packets only with the phone, the TV and the machine itself. Nothing from them went to the internet.

## What this does not show

- Other moments, other versions, or buttons not pressed in those ten minutes.
- What is inside the packets. The remote's traffic is encrypted (TLS); only endpoints and sizes were read.
- The TV's and the phone's own traffic to the internet, which does not pass through the server and which the remote does not change.
- The capture ran on the server itself. A capture taken from outside (the router or a mirror port) would be stronger, because a compromised machine could hide its own packets.

A capture is a photograph of ten minutes, not a standing guarantee. The automated checks (`python test_remote_fast.py`) cover the code itself; see "Checked claims" in the README.

## Repeat it yourself

1. On the machine that runs the remote: `tcpdump -i <interface> -n -w capture.pcap` (stop it with Ctrl+C after a few minutes of use).
2. `tcpdump -n -r capture.pcap | awk '{print $3, $5}' | sort | uniq -c | sort -rn` lists who talked to whom.
3. Every address should be your phone, your TV, or the machine itself. Anything else: find which program owns it with `ss -tunap`.
